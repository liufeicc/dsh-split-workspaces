# dsh-split-workspaces

本地 DSH 插件包：在 Harness Web 界面的主面板里把多个工作区**上下左右平铺**，
每个窗格一个工作区对话，分隔条可拖动改尺寸、标题栏可拖动交换两格位置，
当前获得焦点的窗格用品牌色标题栏标出。

## 它加了什么

- 侧边栏的一行图标（两个平铺格子，紧邻 Plugins 图标），点它把主区切到
  **多工作区平铺**面板。
- 面板本身：顶部只有标题和 `添加工作区`，下面是棋盘 —— 每个窗格都有
  自己的标题栏（工作区名与路径、`打开目录` 图标、`分屏` 图标、模式选择、MCP 开关、会话选择、关闭），
  窗格内部复用共享的 `conversation.content` Factory（`embedded` 变体），挂在显式的
  `SessionProvider` 绑定下，因此每个窗格都是一个完整对话（记录、输入框、流式输出）。
- **`打开目录` 图标**（工作区名右边那个文件夹）：点它把**这一格**的工作区目录交给
  系统文件管理器（Linux 的 `xdg-open`、macOS 的 Finder、Windows 的资源管理器）。
  它没有自己实现这套东西，而是复用已经装好的 Session 远端命名空间
  （`@deepseek-ai/dsh-api-session-controller`）那两个方法：
  `canOpenWorkspacePath()` 先回答「这个部署能不能把路径交给桌面」（没有图形环境的
  Linux 容器答 false，那正是「你面前没有文件管理器」的意思），`openWorkspacePath({ path })`
  再在组合文件系统里**校验**这个路径确实是 Host 上能打开的目录，然后按操作系统的关联
  打开它 —— 目录的关联就是文件管理器。于是「用哪条命令打开」只有一份实现、一套校验，
  本插件也不必在 Host 上加一行、不需要用户重启。
  可用性是部署级事实，只问一次；目录不在 Host 映射里、文件管理器起不来、这个部署
  没有会话服务、压根没有图形环境，都在窗格自己的错误行里说清（本地化原因在前，
  Host 的原文当细节附在后面）。
- **`替换工作区` 图标**（每格标题栏各一个，夹在「打开目录」与「分屏」之间）：把**这一格**
  换成另一个工作区，菜单与面板顶部的 `添加工作区` 同款 —— 一行 `新建工作区…`（复用同一个
  文件夹选择器与注册流程），加上**还没铺开**的工作区列表；已经铺在棋盘上的工作区不在候选里
  （它已经在别的格子上，想把两格对调用「拖动标题栏交换位置」，那条路不重开对话）。
  选中后**位置不变**：布局树、分隔条比例、与邻居的关系一个字节都不动，只把这一格的工作区与
  对话换掉 —— 旧工作区的会话引用因此被释放，这一格改为跟随新工作区最近更新的会话；
  这一格暂存的 Agent 模式留着（它是用户为这一格选的，与工作区无关）。
  做成「每格一个图标」而不是面板顶部一个按钮，是为了永远不必回答「替哪一格」。
- **`切换会话` 下拉里每一行都有一个删除按钮**（行尾的垃圾桶图标）：点它永久删掉**那一行**
  的会话 —— 不必是这一格当前正显示的那一个，而这正是做成「逐行」而不是「菜单底部一个按钮」
  的理由：菜单里摆的就是一列会话，想清的往往正是**别的**那一行，底部一个按钮会让人先去推理
  「它删的是哪一个」。删除本身不在本插件里实现：本插件把「哪一行、叫什么名字」交给
  `dsh-session-delete` 已经装好的**确认弹窗**（该插件的客户端半边用 `ctx.provide` 发布的
  `sessionDeleteUi` 服务，本插件在点击时用 `ctx.get` **惰性解析**，与 MCP 策略那条路同款）。
  于是确认、「会话正在运行就先停下来再删」、删完通知会话列表这几件事都只有一份实现。
  删成功后本插件把**所有**钉着这个会话的窗格一起松手（同一个会话可能同时显示在好几格上 ——
  跟随型窗格会自动选中本工作区最新的真实对话）：跟随型窗格随即回退到本工作区最新的
  真实对话，用户亲手选过会话的分屏窗格回到「选择会话 / 新建会话」的空态。没装
  `dsh-session-delete` 时按钮照样在，点一下会在窗格错误行里明说「删除会话失败：……删除服务」，
  而不是假装删掉了。
- **平铺方式**：`添加工作区` 总是把新窗格接到整块棋盘的右边；每个窗格标题栏上的
  **分屏菜单是两步**：第一步选方向（向左、向右、向上、向下），第二步选**要放进新窗格的
  工作区**。选完方向不会立刻分屏，也不会顺手把当前窗格的工作区再开一格 ——
  平铺的意义就是把**不同**工作区摊开看。于是任意组合都能拼出来，
  例如「上排两个并排、下排一个」= 先把 A 向下分（选 C），再把 A 向右分（选 B）。
  第二步里除了列出现有工作区，还有一行 `新建工作区…` 可以直接挑一个新目录。
  一个图标按钮加两段菜单，比排四个按钮更省标题栏宽度。
- **拖动改尺寸**：窗格之间是一条可拖动的分隔条，左右布局就左右拖，上下布局就上下拖；
  双击分隔条恢复均分，聚焦分隔条后按方向键可微调（按住 Shift 步长更大）。
  比例按「占容器的百分比」保存，因此窗口缩放后布局比例不变。
- **拖动标题栏交换位置**：按住窗格标题栏（里面的按钮、下拉、菜单面板除外）拖到**另一个窗格**上
  松手，两个窗格就交换位置。拖动途中只有落点那一格亮起强调色圈、被拖的那格淡出，
  **松手才交换**；落在空白处松手什么都不做。它换的是**位置**不是内容：两格各自的工作区、
  会话、预选模式都跟着自己走，因此高亮与键盘光标也跟着被拖的那一格去到新位置
  （交换后光标会等一帧重新安放进它的输入框，理由与「关窗格要等一帧」同源）。
  移开不到 4 像素的按下仍然算**单击**（点亮窗格、送光标），于是标题栏依旧是「点一下聚焦」的把手。
  没有 Esc 取消、没有拖到边缘分屏、没有键盘交换 —— 那几条都是「松手才交换」之外的额外语义。
- **焦点高亮**：在哪个窗格里按下鼠标或按 Tab 进入，那一个窗格就成为当前焦点 ——
  只有它的**整条标题栏是蓝色渐变 + 白字**（工作区名、路径、模式/会话触发器、按钮一起变白），
  窗格本身仍是和其他窗格一样的细边框，不加高亮框、不加外发光；
  关掉焦点窗格时，焦点自动交给顶替它位置的那个窗格。
- **键盘光标跟着高亮走**（一条不变量，两个方向都要成立）：窗格被点亮时，光标也进它的输入框；
  反过来，用户点在窗格里的**控件**上（标题栏按钮、下拉、消息里的复制按钮、链接、输入框本身），
  光标就留在那儿，绝不抢。少了前半条会出很难自查的错 —— 点开右边窗格的消息区、以为在跟它说话，
  打出来的字却进了别处；少了后半条会毁掉标题栏的键盘可达性与弹出菜单。
  用户刚拖选出一段文字时也一个字都不碰（`focus()` 会把那段选区整段抹掉，见坑 5）。
  关掉当前窗格时，顶替它的窗格在**下一次重排之后**接管光标（它会重新挂载，理由同样在坑 5）。
  窗格里没有可打字的输入框时（还没会话、宿主 inert），只切高亮、不动光标。
  渐变两端是把蓝色强调色与静态黑 token 混出来的（`color-mix`），既做出图里那种由深到浅的
  蓝，也把白字的对比度抬到 4.5:1 以上 —— 纯强调色配白字只有 3.3:1，偏糊。
  离线测试会把渐变逐端算一遍对比度，低于 4.5:1 直接判失败。
  焦点标题栏上的按钮（分屏图标、模式/会话下拉、关闭）在 hover / 展开时用的是**黑色压深**，
  而不是拿白色调淡：白字配「白 24% 压出来的浅灰蓝底」只有 3.5:1，看着就是一块灰底、字糊在
  上面；改成黑底后 hover 是黑 50%（底仍透出一点蓝）、展开是纯黑，同一处白字分别有 11:1 与
  21:1，离线测试同样逐端算一遍。
- **`Alt+方向键` 搬焦点**：按 `Alt+←/→/↑/↓` 把焦点交给**那个方向上相应位置**的窗格，
  并把键盘光标一起送进它的输入框（于是切过去就能直接打字，全程不用碰鼠标）。
  方向按窗格的**矩形**判定，不是按布局树的嵌套关系：候选必须整个在那个方向之外，
  且垂直方向上有重叠；距离近的优先 → 重叠多的优先 → 中心更对齐的优先。
  于是「上排 A|B、下排 C|D」里 A 按 `Alt+↓` 只会到 C（D 与 A 一行重叠都没有），
  「A | X | B」三连排里 A 按 `Alt+→` 先到紧挨着的 X 而不是跳过它。
  走到最边上再按**不动**（不绕回对面）：循环会让人在满屏窗格之间迷失方向。
  这四个键位同时登记进框架的快捷键名册，因此能在 **设置 → 快捷键** 里看到，
  也不能再被分配给别的命令。
- **下拉菜单面板的底色**用「抬升表面」`--dsw-alias-bg-layer-2`（深色 #2c2c2e / 浅色 #fff），
  不用 `--dsw-alias-bg-overlay` —— 后者在深色主题里是 #61666b 的中灰，面板上白字只剩 5.6:1、
  次要文字（「当前」「当前会话已开始…」）只有 3.9:1。换底色后深色主题下分别是 13.3:1 与
  9.3:1。连带把菜单项的 hover 从 `bg-layer-2` 换成 `currentColor 8%`：面板自己就是
  `bg-layer-2`，再拿它当 hover 底等于按下去没反应。
- **每个窗格独立的 Agent 模式选择器**（标准 / PTC / 极简 / 创造，外加自定义预设）：
  和侧边栏新建任务用的是同一份 Host 花名册（`remote.agentPresets.list`），
  既标出窗格当前会话运行的模式，也标出为下一个会话预选的模式。
- **按工作区共享的 MCP 工具开关**（标题栏上的 `MCP` / `MCP n` 下拉）：勾选哪些 MCP
  服务器的工具对这个工作区可见。它与模式选择器的语义**正相反** —— 模式是「按窗格暂存、
  按会话生效」，而 MCP 可见性是宿主按**会话 cwd** 施加的策略，因此同一工作区的所有会话
  共享同一份选择。清单与工具数来自 Host（`remote.mcpWorkspace.list`，服务器名从工具名
  `mcp__<server>__*` 自动发现），勾选走 `set`：宿主立刻重挂工具限制并落盘。
  未配置的工作区**默认全不选**，也就是完全不暴露 MCP 工具、不占上下文。
- `添加工作区` 的下拉菜单会列出「还没铺开的工作区」，也支持从文件夹选择器
  （`uiWorkspace.pickDirectory()`，或在 Desktop 下走 preload 桥）**新建**一个工作区。
  同一条「选目录 → 注册工作区」的实现也供分屏菜单第二步的 `新建工作区…` 使用，
  因此两处只会有一套选择器与一套失败处理。

## 行为细节

- 第一次打开棋盘会播种：当前会话所在的工作区排第一，再补一个别的，于是打开就是两个
  窗格并排，而不是一块空白。
- 窗格如何决定显示哪个会话：
  - **跟随型**窗格（`添加工作区` 铺开的）跟随该工作区最近更新的**真实对话**；
  - 一旦手动选了会话（或新建了会话），该窗格就钉在这个会话上；
  - **分屏新开的**窗格先空着，提示「为这个窗格选择会话，或新建会话」——
    这样两个窗格不会莫名其妙地显示同一段对话。它显示哪个工作区，是分屏菜单第二步
    选出来的。
- **空白会话不进列表**：建了会话但一条消息都没发过的（Host 里 `blank: true`）
  不会出现在 `切换会话` 菜单里，也不会被跟随型窗格选为「最新会话」——
  否则误点几次「新建会话」就会堆出一长串同名「新会话」。这与 DSH 原生侧边栏
  「空白会话只显示当前选中的那一个」是同一个思路，只是这里做得更彻底：菜单第一项
  本来就是 `新建会话`，占位行没有额外价值。
- **`新建会话` 优先复用空白会话**：本工作区里已经有空白会话、且它没被别的窗格
  钉住时，直接切过去（仍应用该窗格暂存的模式），不再让 Host 新建一条空记录；
  只有没有可复用的空白会话时才真正创建。于是反复点 `新建会话` 最多只回到同一个
  空白会话，不会在 Host 的会话表与磁盘里留下永远不用的空壳。
- **分屏菜单第二步的候选**：列出**全部**工作区，但还没铺开的排在前面（分屏的第一
  意图就是再摊开一个工作区），已经铺在别的窗格里的排在后面并把右边提示换成
  `已打开`（其余显示路径）。保留已铺开的工作区是有意的：同一个工作区开两格看两个
  会话是合理用法，而且所有工作区都铺开之后，分屏仍然有别的工作区可选。
  `返回` 那一行右边会显示当前选中的方向，因此第二步里也看得见这次是往哪边切。
- **`替换工作区` 的候选与 `添加工作区` 是同一份**（模型里的 `unopenedWorkspaces`：工作区清单
  里去掉已经铺在棋盘上的那些），因此两处菜单的排序、以及「还没有工作区」与「没有别的工作区
  可换了」这两句话天然一致。第二种情况是两种不同的处境：一个工作区都没注册过（棋盘上那一格
  是靠文件夹选择器刚长出来的）与「别的工作区都铺在棋盘上了」，用户能做的事不一样。
  候选里刻意不含已经铺开的工作区：选中它意味着「同一个工作区占两格」，而替换的意图是
  「换一个工作区进来」；真要对调两格用拖动标题栏那条路，它不重开对话。
- **第二步的 `新建工作区…`**：一个工作区都没注册过时它照样在，于是棋盘仍能长出第一格。
  点它会打开文件夹选择器，选中的目录注册成工作区后直接切进新窗格；用户取消就什么都不做，
  选择器本身打不开时窗格上会写明是「无法打开文件夹选择器」，而不是含糊的添加失败。
  方向在关菜单之前就抓进了局部变量 —— 关菜单会把 `splitDirection` 复位，等到选择器
  回来时已经读不到了。
- 分屏菜单是**受控**弹出菜单（`Popover` 的 `open` + `onOpenChange`）：只有它能被外部
  复位。点方向、选工作区、点别处、按 Esc —— 任何一种关闭都会把菜单复位回第一步，
  否则下次打开会停在上次选的方向上。离线测试对「选完工作区后」与「点别处关闭后」
  两条路径各有一条断言。
- 每个窗格各自持有 `ctx.sessions.retain(..., { source: 'splitWorkspaces' })` 引用，
  所以侧边栏的主选择不受影响，多个会话可以同时开着。
- **拖动交换位置不会重开会话**：交换的是布局树里两个叶子的 key，窗格记录（工作区、会话引用、
  预选模式）一个字段都不动，于是两个窗格的 `useSessionReference` 效果一次都不重跑 ——
  引用不松手，对话的历史与本地状态就整段留着。这条路只在**同一层**分屏里成立
  （React 只在兄弟节点之间按 key 搬动），跨层交换仍然会重建那两棵子树，见坑 6。
- 窗格列表与布局树保存在插件里（不是 React 状态），因此切回 Conversation 面板再切回来
  不会丢；刷新页面才重置。
- 模式选择是「按窗格」的：会话还是空白时选择立刻生效（`remote.agentPresets.select`）；
  会话已经跑过回合时 Host 会拒绝改标签，此时选择被暂存，菜单里标注 `下一个会话`，
  等该窗格下一次新建会话时应用。被拒绝的原因会显示在窗格上，且不会影响会话创建。
- MCP 开关是「按工作区」的（与上一条正相反）：选择存在**工作区路径**上，关掉再开的窗格
  读到的还是同一份；改动立刻作用于该工作区的**所有会话**（含已经跑过回合的），不需要
  新开会话。宿主服务由 `@local/dsh-mcp-workspace-policy` 提供（含按 cwd 施加
  `tools.restrict` 的策略与落盘），本插件只是它的界面。
- 没挂预设注册表的部署会得到 `gateway/invocation-unavailable`，此时棋盘照常工作，
  只是不显示模式选择器。
- `添加工作区` 不会顺手创建会话，也不会把主面板切走。
- **焦点键的作用范围是「这个面板在屏幕上」，不是「焦点在窗格里」**：监听挂在文档的捕获
  阶段，面板没显示时（棋盘根节点的标记不在）什么都不做，因此点过棋盘空白、刚用侧边栏图标
  切过来这类「焦点落在 `body` / 侧边栏」的情形照样管用 —— 这一条是用户实测报回来的，
  见下面的坑 4。浮层（菜单 / 对话框）盖着时、焦点在棋盘之外的输入框里时一律放行：
  那些键是别人的（「设置 → 快捷键」的按键录制就在浮层里）。
  切过去之后键盘光标会跟着进目标窗格的输入框；目标窗格还没有会话、没有可编辑的输入框时
  只切高亮，**不把光标从原来那个窗格里抢走**。
- **鼠标点亮窗格时的光标归属**：送光标挂在 `click` 上（**不是** `pointerdown`），并且**放弃**
  两类落点 —— 落点是控件（按钮 / 链接 / 菜单项 / 输入框 / 可编辑区），以及用户刚拖选出
  一段文字（选区不是折叠的）。前者是为了不打断「用户正在操作那个控件」，后者是因为
  `focus()` 会实测把那段选区整段抹掉。两条都是真浏览器量出来的，见坑 5。
  `Tab` 进窗格只切高亮、不搬光标：Tab 的落点是浏览器的地盘，标题栏按钮与会话区里别的
  可聚焦元素都要能 Tab 得到。

## 踩过的六个坑（改这块代码前先读）

1. **焦点用错了颜色 token。** `--dsw-alias-brand-primary` 在深色主题里是**近白**的中性
   填充色（`--dsw-static-neutral-bluish-50`），拿它当焦点标题栏的底色再配白字会得到
   白底白字。蓝色强调色是 `--dsw-alias-brand-primary-new-colorprimary-new-color`
   （浅色 #4176e6 / 深色 #5686fe），兜底用静态的 `--dsw-static-deepseek-500`，
   **不要**把它兜底到那支中性填充色。离线测试里有两条断言守住这件事。
   另外白字直接压纯强调色只有 3.3:1，所以渐变两端要跟黑混一下把蓝压深。

2. **标题栏里的可选孩子必须带 key。** React 对没有 key 的兄弟节点是按位置匹配的：
   焦点标记、模式选择器这类「有时有、有时没有」的孩子一旦出现/消失，位置就会错开，
   React 会把用户刚按下鼠标的那个按钮**复用**成别的控件，`click` 于是落到错误的处理
   函数上。真实症状是「点『向下分屏』却变成向右分屏」。现在标题栏、错误行、对话本体
   都带固定 key，离线测试会检查「key 齐全且唯一」「焦点切换前后标题栏结构完全一致」。

3. **焦点键为什么是 Alt，以及为什么必须挂捕获阶段。** 这组键要在输入框里也能用，
   而 Chromium 的 contenteditable 已经把常用的方向键组合占满了：
   `Shift+←/→` 逐字选字、`Shift+↑/↓` 按行选字、`Ctrl+←/→` 按词跳光标、
   `Ctrl+↑/↓` 跳段首段尾、`Ctrl+Shift+←/→` 按词选字。所以 Shift 或 Ctrl 单独配方向键
   都会废掉输入框里的一个高频操作。`Ctrl+Alt+方向键` 看着像个出口，实际上被桌面环境
   拿走了（GNOME/Unity 的 `switch-to-workspace-{left,right,up,down}` 就是
   `Ctrl+Alt+方向键`，在窗口管理器那一层就被吃掉，页面根本收不到）。
   **只有 `Alt+方向键` 在输入框里没有任何原生含义、桌面也不占**，代价最小；
   它唯一的牵扯是浏览器里 `Alt+←/→` 的前进后退 —— 所以处理必须挂在**捕获阶段**并
   `preventDefault()`（同时 `stopPropagation()`，免得输入框再把它当光标操作处理一遍）。
   `AltGraph`（某些布局上等于 Ctrl+Alt）与输入法组字中一律放行，绝不抢输入法的键。

4. **键盘处理不能挂在棋盘节点上。** 第一版把它挂在棋盘根节点的 `onKeyDownCapture` 上，
   理由是「捕获阶段才能在输入框之前拿到事件」—— 这条没错，但它还藏了一个错假设：
   事件目标一定在棋盘里。实际点过棋盘空白之后焦点会落到 `document.body`，刚用侧边栏
   图标切过来时焦点还在侧边栏按钮上；这两种情况下事件都不流经棋盘节点（合成事件只沿
   目标的祖先链派发），按键全都没反应 —— 用户看到的现象就是「只有焦点在输入框里时
   `Alt+方向键` 才有效」。现在监听挂在 `document` 的捕获阶段（仍然早于输入框），
   并用棋盘根节点的标记判断面板在不在屏幕上：主面板是按 key 渲染的，切到别的面板时
   棋盘会卸载、标记随之消失，处理自然失效，不需要额外记账。

5. **「点亮窗格就送光标」有两处只有真浏览器才答得上来的行为。** 离线测试的假 `document`
   模拟不了浏览器的**默认动作**，这三条都是拿无头 Chrome + CDP **可信鼠标输入**量出来的
   （`node tools/browser-probe.mjs` 会把前两条逐条再跑一遍，不需要 DSH 服务）：
   - **不能挂在 `pointerdown` 上**：单击一个不可聚焦的元素（消息段落就是）时，`mousedown`
     的默认动作会把当前焦点抹成 `body` —— 在 `pointerdown` 里 `focus()` 出来的光标紧接着
     就被这一步擦掉。挂到 `click` 上才留得住（`click` 之后没有会改焦点的默认动作）。
   - **不能无条件聚焦**：在 `click` 里对一个 contenteditable 调 `focus()`，会把刚拖出来的
     选区**整段抹掉**（实测：选区从 `ectable text here` 直接变成空、折叠）。这等于把
     「选中消息复制」废掉，所以只要选区不是折叠的就一个字都不碰。单击时先到的那次
     `mousedown` 已经把旧选区清掉，因此不会因为页面上某处留着陈年选区而永久失灵。
   - **关窗格要等一帧**：顶替焦点的窗格原来嵌在被折叠掉的那层分屏里，布局树塌陷后 React
     按 key 找不到原来那棵子树，只能重建 —— 立刻 `focus()` 只会聚焦到一个马上要被丢掉的
     旧输入框，重排一结束光标就没了。等一帧（`requestAnimationFrame`，没有它的环境退回
     `setTimeout`）再聚焦，才落在真实存在、且会继续存在的那个输入框上。

6. **交换两个窗格的位置只能靠「换 key」，而且 React 只在兄弟节点之间搬动。**
   同一个效果有过三种写法，只有第三种是对的：
   - **换两个窗格记录里的工作区 / 会话**：两边 `useSessionReference` 的效果都会重跑，而 DSH 的
     会话引用契约是「最后一次释放就拆掉会话的本地作用域与历史」—— 两个对话都会白重开一遍。
   - **把布局树里的叶子整棵换过去**：结构共享失效、整条路径重建，React 按 key 找不到原来的
     子树，只能卸载重建，同样白重开。
   - **只把布局树里两个叶子的 `key` 互换**（模型里的 `swapLeaves`，存储层 `swapPanes`）：
     分屏的层级与比例、窗格记录一个字段都不动。于是在 React 眼里这仅仅是「同一层里的两个
     兄弟换了 key」，它会**整体搬动那两棵子树**，会话引用一次都不松手。

   第三种还依赖一个前提：**叶子窗格必须是分屏 div 的直接孩子**。原来每个孩子外面还套着一层
   占位 div（比例写在它身上），而 React 的 key 匹配只发生在同一个父节点下 —— 隔着一层就配不上，
   交换会悄悄退化成重建。现在比例写在窗格自己的 `flexGrow` 上，占位 div 只留给子树。

   **跨层交换（两方不在同一层分屏里）仍然是重建。** `A | (B/C)` 里把 A 和 C 换位置，React 没法把
   一棵子树搬到另一个父节点下，只能卸载重建；实测那一格会闪一下「正在打开会话…」
   （本地小会话下无头 Chrome 多次量到 50~245ms，三五帧到十几帧），格内的滚动位置与展开后的
   工具输出也会重置。同层交换（任意两个同层或相邻的窗格）完全没有这些代价 —— 这是
   「拖动交换位置」敢做的前提，真浏览器探针把这两件事分别量一遍并如实报告：
   `node tools/swap-probe.mjs`。
   若哪天想让跨层交换也免掉这一下，得改**会话引用的生命周期**（同一个会话的引用在多个窗格间
   共享，最后一次释放延后一个任务执行，让同一次重排里的卸载 + 重挂抵消掉），而重建本身带来的
   滚动与展开状态丢失仍然免不掉 —— 代价不小、收益只有几十毫秒，暂时不做。

## 文件

源码按职责拆成几个文件（都远小于 800 行）。DSH 的浏览器模块系统支持**包内代码块**：
入口用 `require.async('./client.xxx.js')` 请求同目录文件，宿主按
`/plugins/<包名>/client.xxx.js?rev=<版本>` 提供，因此入口不必背着全部实现。

- `client.js` —— 入口：装载各代码块（样式 / 词典 / 模型 / 模式 / MCP / 菜单 / 窗格 / 视图）、
  注册插槽、注入样式，把 `Alt+方向键` 登记成框架的固定快捷键，并在文档上装上它的键盘处理；
  另外提供 `openWorkspaceDirectory(path)`（走 `remote.session.openWorkspacePath`）
  给窗格的「打开目录」按钮，以及 `requestSessionDelete(sessionId, displayTitle)` ——
  惰性解析 `dsh-session-delete` 的 `sessionDeleteUi` 服务，把「删除这一行」转交给它的确认弹窗，
  并在删成功后用 `paneStore.forgetSession` 松开所有钉着这个会话的窗格。
- `client.view.js` —— 棋盘层：`Splitter`（分隔条）、`PaneBody`（窗格里的对话）、
  `SplitPanel`（按布局树渲染窗格与分隔条、面板顶部动作、棋盘根节点上的「在屏幕上」标记）、
  `installPaneKeys`（文档级的 `Alt+方向键` 处理，聚焦交给窗格块的 `focusPaneInput`）。
- `client.pane.js` —— 窗格层：`PaneFrame`（工作区标题、**打开目录按钮**、**替换工作区图标**

  与它持有的会话引用；
  **标题栏上的拖动交换**（按下抓指针 → 越过阈值才
  起拖 → 命中测试找落点 → 松手换位置，外加「刚拖完的那次 click 不再抢光标」）；

- `client.menu.js` —— 菜单零件：`Popover`（含受控开关）、`MenuItem`、`MenuDeleteButton`

  按钮套按钮是无效 HTML）、各处的 svg 图标

  跨层交换会被如实报告为重建，见坑 6）。顺带把拖动途中的反馈截成 PNG 打印路径
  （`node tools/swap-probe.mjs`，约两分钟；可用 `DSH_SWAP_PROBE_URL` 复用一个已经开着的服务）。

## 本地开发

Profile 以 `link:` 指向本目录，`dsh-client-hmr` 会按 500ms 轮询**入口** `client.js`
（mtime / ctime / 大小），所以改入口就会在约一秒内自动重载浏览器插件，不需要构建。

注意：HMR 只盯着入口文件，而代码块 URL 带着「入口文件的 mtime / ctime / 大小派生的版本号」，
因此**改完代码块（`client.*.js`）必须顺手动一下入口**（例如 `touch client.js` 或
改一行注释），否则浏览器既不重载、旧版本缓存也还在：

```bash
touch client.js
```

改动行为时请一并跑全部离线测试（零依赖，秒级）：

```bash
node test/layout-contract.mjs
node test/drag-contract.mjs
node test/focus-contract.mjs
node test/preset-contract.mjs
node test/open-contract.mjs
node test/mcp-contract.mjs
node test/delete-contract.mjs
```

改到「光标归属」那块时，另外跑一遍真浏览器探针（需要 `google-chrome`，约十秒）：

```bash
node tools/browser-probe.mjs
```

改到「替换工作区」那块时，跑第三个真浏览器探针（同样需要 `google-chrome` 与 `dsh`，
约一分钟；`DSH_REPLACE_PROBE_URL` 可复用一个开着的服务）：

```bash
node tools/replace-probe.mjs
```

改到「拖动交换位置」那块时，跑另一个真浏览器探针（需要 `google-chrome` 与 `dsh`；
它会自己起一个独立的 web 服务，约两分钟）：

```bash
node tools/swap-probe.mjs                                  # 自己起服务
DSH_SWAP_PROBE_URL='http://127.0.0.1:PORT/?token=…' \
  node tools/swap-probe.mjs                                # 或复用已经开着的服务
```

想在**真实页面**上看这套行为，可以用另一个无头客户端点一遍（不影响自己开着的窗口）：
`dsh web --no-open --port 0` 会打印带令牌的 URL，把它交给无头 Chrome，然后
①切到平铺面板 ②点某个窗格标题栏里的工作区名 → 光标应当进那个窗格的输入框
③点标题栏的「分屏」按钮 → 焦点应当留在按钮上、不进输入框
④在窗格里拖选一段文字 → 选区必须还在（说明守卫给选区让路了）
⑤点当前窗格的关闭按钮 → 顶替它的窗格应当在下一帧接上光标
⑥按住某个窗格的标题栏拖到另一个窗格上松手 → 两格交换位置，且**两边的对话都不重开**
（交换前后各看一眼窗格里的消息还在不在、有没有闪出「正在打开会话…」）
⑦在有空闲工作区时点某一格标题栏的「替换工作区」图标 → 菜单第一行是「新建工作区…」、
下面是还没铺开的工作区；选一个 → **这一格的位置与大小都不变**，里面换成新工作区的对话
（旧对话消失、不残留），其余格子一个像素都不动。
